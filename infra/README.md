# Hades infrastructure (AWS CDK, TypeScript)

The `HadesStack` deploys these resources (default region `us-west-2`, or set `CDK_DEFAULT_REGION`):

- **DynamoDB** table `hades_journal` with `pk`/`sk` strings, on-demand billing and PITR. It has a stream (`NEW_AND_OLD_IMAGES`) that feeds the notes indexer. The table is retained when the stack is deleted.
- **S3 notes bucket** (CDK-generated name) holding note content at `users/<sub>/notes/<path>`. It is versioned, SSE-S3 encrypted, has all public access blocked and enforces SSL. Lifecycle rules expire noncurrent versions after 90 days, remove expired object delete markers and abort incomplete multipart uploads after 7 days. The bucket is retained when the stack is deleted.
- **Cognito** user pool with email sign-in and no self sign-up. It has a public web client that allows SRP and USER_PASSWORD auth.
- **API Lambda**, the `backend` binary built from `../backend` (Rust, arm64, `provided.al2023`) with `cargo-lambda`. It gets `TABLE_NAME`, `NOTES_BUCKET`, the Cognito IDs, `VECTOR_BUCKET`, `VECTOR_INDEX` and `EMBED_MODEL_ID` as env vars. Its permissions are read/write access to the table, read/write/delete (including versioned get and delete) on `users/*` in the notes bucket, `s3vectors:QueryVectors` and `s3vectors:GetVectors` on the vector index, and `bedrock:InvokeModel` on Titan Text Embeddings V2.
- **Notes search (phase 2):**
  - An **S3 Vectors** bucket (name generated by CloudFormation) with one index, `notes`: `float32`, dimension 1024, `cosine`, with `heading`, `snippet`, `title` and `updatedAt` as non-filterable metadata. Both are retained when the stack is deleted. The vectors can be rebuilt with a backfill.
  - An **indexer Lambda**, the `indexer` binary from the same crate (arm64, 512 MB, 5 min timeout for the backfill). It is triggered by the table stream, filtered to `pk` starting with `NOTE#`, with batch size 10, a 5 s batching window, bisect on error, 3 retries and partial batch failure reporting. Failed records go to the `IndexerDlq` SQS queue, which keeps them for 14 days. Its permissions are `s3:GetObject`/`s3:GetObjectVersion` on `users/*` in the notes bucket, `GetItem`/`Query`/`Scan`/`UpdateItem` on the table, `PutVectors`/`DeleteVectors`/`GetVectors` on the index, and `bedrock:InvokeModel` on Titan V2. The event source grants the stream read permissions.
- **API Gateway HTTP API**, with a `$default` route to the Lambda. Auth is enforced in the app.
- **S3 + CloudFront** for the SPA:
  - `/*` is served from S3 through OAC. A CloudFront Function serves `/assets/*` and top-level files (`/config.json`, `/favicon.svg`) as-is and rewrites every other path to `/index.html`, including note URLs such as `/notes/Projects/Design.md`.
  - `/api/*` is proxied to the HTTP API with no caching.
- `config.json` is written into the site bucket at deploy time: `{ apiUrl: "/api", region, userPoolId, userPoolClientId }`.

## Prerequisites

- Node 20+ and npm. The CDK CLI is a dev dependency, so use `npx cdk`.
- Rust toolchain (`rustup`).
- **cargo-lambda** and **zig**. cargo-lambda uses zig to cross-compile. Install with one of:
  - `pip install cargo-lambda`, which also installs the `ziglang` package. With uv, use `uv tool install cargo-lambda`.
  - `cargo install --locked cargo-lambda`, then install zig separately (for example `pip install ziglang`, or your package manager).

  Check with `cargo lambda --version` and `zig version`. If zig only came from pip, cargo-lambda may not find it. In that case, put the zig binary on `PATH`, e.g. `ln -s <venv>/lib/python3.x/site-packages/ziglang/zig ~/.local/bin/zig`.
- AWS credentials for the target account (`aws configure` / `AWS_PROFILE`).
- **Bedrock model access** to Amazon Titan Text Embeddings V2 (`amazon.titan-embed-text-v2:0`) in the target account and region. If indexing or search fails with an `AccessDeniedException` from `InvokeModel`, check the Bedrock console under **Model access**.

## First-time setup

```sh
cd infra
npm install
npx cdk bootstrap        # once per account/region
```

## Deploy

Build the frontend first. If `frontend/dist` is missing, the site deployment is skipped and synth prints a warning.

```sh
cd frontend && npm install && npm run build
cd ../infra && npx cdk deploy
```

`npx cdk synth` builds both Rust binaries (`backend` and `indexer`) with cargo-lambda. The first build takes several minutes.

The stack outputs are `CloudFrontUrl`, `HttpApiUrl`, `TableName`, `NotesBucketName`, `UserPoolId`, `UserPoolClientId`, `Region`, `VectorBucketName`, `VectorIndexName`, `IndexerDlqUrl` and `IndexerFunctionName`. To fetch them later:

```sh
aws cloudformation describe-stacks --stack-name HadesStack \
  --query 'Stacks[0].Outputs' --output table
```

### Backfill the search index (once)

The stream only covers changes made after it was enabled. After the first phase 2 deploy, index the notes that already exist:

```sh
aws lambda invoke --function-name <IndexerFunctionName output> \
  --payload '{"backfill":true}' --cli-binary-format raw-in-base64-out /dev/stdout
```

This reindexes every note whose `indexedHash` differs from its `contentHash`, so it is safe to run again. Records that keep failing end up in the `IndexerDlqUrl` queue.

## Create a user

Self sign-up is disabled, so an admin has to create users:

```sh
POOL_ID=<UserPoolId output>
EMAIL=you@example.com

aws cognito-idp admin-create-user \
  --user-pool-id "$POOL_ID" \
  --username "$EMAIL" \
  --user-attributes Name=email,Value="$EMAIL" Name=email_verified,Value=true \
  --message-action SUPPRESS

aws cognito-idp admin-set-user-password \
  --user-pool-id "$POOL_ID" \
  --username "$EMAIL" \
  --password 'A-strong-Passw0rd!' \
  --permanent
```

## Get an access token (for curl testing)

```sh
CLIENT_ID=<UserPoolClientId output>

TOKEN=$(aws cognito-idp initiate-auth \
  --auth-flow USER_PASSWORD_AUTH \
  --client-id "$CLIENT_ID" \
  --auth-parameters USERNAME="$EMAIL",PASSWORD='A-strong-Passw0rd!' \
  --query 'AuthenticationResult.AccessToken' --output text)

curl -H "Authorization: Bearer $TOKEN" https://<CloudFrontUrl>/api/journal
```

The backend needs the **access** token, not the ID token.

## Local development

Local development runs against the deployed DynamoDB table, notes bucket, vector index and Cognito pool, using your local AWS credentials. Search also calls Bedrock, so your credentials need `bedrock:InvokeModel` and `s3vectors:QueryVectors`/`GetVectors`. The indexer is not run locally: notes saved locally are indexed by the deployed indexer through the table stream.

Backend (listens on `http://localhost:3000`, routes under `/api`):

```sh
export AWS_REGION=us-west-2
export TABLE_NAME=hades_journal
export NOTES_BUCKET=<NotesBucketName output>
export COGNITO_USER_POOL_ID=<UserPoolId output>
export COGNITO_CLIENT_ID=<UserPoolClientId output>
export VECTOR_BUCKET=<VectorBucketName output>
export VECTOR_INDEX=notes                    # VectorIndexName output
export CORS_ORIGINS=http://localhost:5173   # default
cd backend && cargo run --bin backend
```

Frontend:

```sh
cd frontend
cp public/config.example.json public/config.json
# edit public/config.json: set region, userPoolId, userPoolClientId from the outputs;
# keep apiUrl = "http://localhost:3000/api"
npm run dev
```

## Notes

- The table, user pool, notes bucket, vector bucket and vector index use `RemovalPolicy.RETAIN`, so `cdk destroy` leaves them in place. The notes bucket is the source of truth for note content and is never emptied by CDK. Delete it by hand (including all object versions) if you really want it gone. The site bucket is destroyed and emptied.
- Never commit `frontend/public/config.json`. In production, the deployed `config.json` from CDK overrides any file with the same name in `dist`.
